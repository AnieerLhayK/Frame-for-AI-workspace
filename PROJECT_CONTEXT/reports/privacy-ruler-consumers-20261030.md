# Privacy-Ruler 个人技能引用审查

日期：2026-10-30。需求与规格：PLAN-20261030-001；执行：TASK-20261030-007。
基线：5eb14077；本报告检查本轮源码状态，逐源指纹见同目录 JSON 清单。

## 结论与接入顺序

建议先接入以下五个技能的**对外资料交付分支**，不改变其所有调用的默认行为：

1. `character-generator`：已授权语料进入生成流程前，生成独立脱敏副本；保留语言研究损失说明。
2. `showcase-packer`：限定在原有允许范围内的资料打包分支；处理后重新生成内容哈希和审批计划。
3. `cover-it`：用户已授权保存对外回顾时，先处理资料副本；仅对话或本人阅读分支不触发文件写入。
4. `research`：选定的私人来源或摘录要交给外部 AI/协作者、或进入公开报告时处理，不改原始证据。
5. `diagnosing-bugs`：已授权保存的日志/诊断材料要交给外部时处理；先在私人位置捕获，避免先打印原值再遮蔽。

本轮仅形成建议，没有批量修改以上消费者。`handoff` 同样有明显需求，但其登记为 text_only，
不能因为指令要求保存交接文档就推定获得写权限；应单独解决既有契约冲突后再接入。

## 共用调用契约

仅 Codex 分支可以调用。其他平台应显式报告未运行，不能自动声称享有同等覆盖。
调用方传递已有授权的精确资料清单、分享去向、请求档位和新输出位置；不增加资料发现、
来源写入或发布权限。Privacy-Ruler 默认使用 Privacy 子代理；可选择主代理执行。
当前开发会话没有热加载 Privacy 角色，已验证披露后的普通子代理 fallback；不能把配置落盘
等同于命名角色的实际调用成功。调用方必须处理 partial/blocked/failed，禁止忽略失败继续打包。

默认中档；公开网络强制高档。输出保持待人工复核，身份映射和原值对照单独留私。
有文件写入授权的分支才能执行文件处理；text_only 消费者只能提示用户单独调用。
处理改变文件内容后，原审批哈希、签名、引用位置或接口契约需要重新核对。
原有敏感资料排除项和发布审批继续有效，脱敏不是绕过白名单的理由。

## 复现与证据

清单经 `scripts.workspace.manifest_loader.load_manifest()` 聚合获得，仅读取登记源 SKILL.md，
对描述、交付阶段、读写角色、调用方式和平台边界逐项判断。机器清单保存每个来源 SHA-256、
平台、角色及允许模式，可复核本次审查的确切版本。后续源码变化需重新判断，不能把此快照当实时清单。

合成混合批次与普通子代理 fallback 已验证；来源保持只读，私人映射未进入交付，图片对象正确阻止。
命名 Privacy 角色的当前聊天热加载没有验证成功，正常 fallback 已验证；需在加载新配置的会话中再实际验证命名角色。

工程检查包括 Privacy-Ruler CLI 回归、QQ CLI 全出口回归、manifest、协议、技能契约和投影检查。
捆绑 skill-creator 的 quick_validate 尚不接受 Workspace 要求的 `disable-model-invocation` 字段；
保留正确的显式调用配置，不修改系统验证器。Workspace 自身技能校验覆盖该字段及 openai.yaml 一致性并通过。
