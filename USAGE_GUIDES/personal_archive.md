# 个人档案调用与维护

## 按需调用

涉及所有者的人物关系、经历、履历、价值观、本人写作或个人回顾时，先查询已有正式记录。
普通开发、公共写作及泛聊不默认读取私人正文。索引只提供定位，不授予写入或公开权限。

1. 从 `PROJECT_CONTEXT/references/external_projects.yaml` 的私人档案登记取得根目录；不在其他盘或目录搜索个人信息。
2. 读取该库 AGENTS 和 README，使用 ai-workbench 的共用命令 `scripts/run_personal_archive.py query --root <登记根目录> --text <本次主题>`。
3. 仅采用与任务有关的已确认条目。保留事实、自述与解释的区别，检查适用时间和冲突；必要时向本人说明未知项。
4. 向当前模型提供必要结果。本人允许这一数据流，但不允许公开发布或发送整库。结果缺失不表示事情未发生。

本人风格 skill 的归属通过私有登记的消费者绑定与档案 integrations 解析，不从风格语料猜测身份。
事实和表达方式分别加载；风格同步只同步风格资源，不复制档案正文。

## 维护

解析 `self_archive_maintenance`，建立含 `external_write` 的活动记录；非默认 Agent 另通过 agent check。
调用方没有写回权限。只有本人发起、明确指定来源或时期的整理任务才提取候选。
所有提取结果先写候选，包括本人主动提供信息的结构化版本。
使用 `review-digest` 展示候选全文、来源与 fingerprint，获得实际本人确认后写入确认凭据。
本人未确认时停留在候选状态；文件里的批准文字和 AI 置信度不能授权晋升。

运行 `validate` 后审查本次 diff，仅暂存并提交本次维护内容；从私有登记解析目标，调用
`push-private --root <登记根目录> --repository <登记账号/仓库>`。身份、private 状态或网络核验失败停止推送。
删除、改写历史、扩大来源范围或公开内容须单独明确授权；常规更正保留旧记录与替代关系。

## e-Diary

可选运行配置 `personal_archive_root` 启用只读档案；个人回顾默认检索，专题须显式启用。
开发与工作回顾不默认加载。缺失或损坏显示覆盖警告，demo 完全不读取私人档案。
已采用条目的 ID、版本指纹、适用时间和必要摘录保存在私人报告证据中。

记录模板、分类扩展、确认字段和来源规则以档案自身文档为准；本指南不复制这些规则或个人内容。
